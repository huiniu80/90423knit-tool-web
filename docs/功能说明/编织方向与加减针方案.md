# 编织方向与加减针方案

> 文档状态：根据现状整理
>
> 规则归属：逐行边界比较、方向、分片/连接识别、加减针压缩和分段说明以本文为唯一主要说明。

## 一、功能目的

把针格每一行的边界变化转换为用户可读的起针、平织、加针、减针、平收、领口分片和肩部说明，并按实际编织顺序编号。

## 二、使用入口

- 在“绘版”模式查看所有边界段的编织卡。
- 在“针格”模式点击红色轮廓段查看该段编织卡。
- 点击卡片右上角上下箭头，在该对象“自下而上”和“自上而下”之间切换。
- 工具栏在选中闭合织片时显示起针数、总行数和取整待确认状态。

## 三、用户操作流程

1. 完成闭合轮廓、密度、针格策略和必要取整。
2. 选择织片，在绘版或针格模式阅读编织卡。
3. 确认当前方向是从下往上还是从上往下；需要时切换。
4. 按编号顺序查看各边界的加减针阶段、领口起始、左右肩分开和平织行数。
5. 对照针格中的编号标记检查变化发生在哪一行、哪一侧。
6. 若出现不支持或未落入针格，返回修改轮廓、密度或策略。

## 四、当前可观察行为

- **根据现状整理：**每个闭合轮廓独立生成计划，默认自下而上；方向按对象分别保存。
- **根据现状整理：**只处理第一到最后一个有针格的物理行；前后空画布行忽略，中间空行仍进入计划并可能不支持。
- **根据现状整理：**每行最多两个针段时尝试归纳；当前行或前一行超过两个针段即标记不支持。
- **根据现状整理：**一个针段到一个针段时，分别比较左右端点，正变化记加针、负变化记减针。
- **根据现状整理：**一个针段变两个针段时识别为中间收针并分成左右肩；两个变一个时识别为中间加起并连接。
- **根据现状整理：**第一行有两个针段时允许“左右片分别起针”。
- **根据现状整理：**同一侧连续出现相同间隔、相同针数、相同操作时压缩为一个重复规则；顺序保持不变。
- **根据现状整理：**外侧一次减超过一针在画布卡中称为“平收”；其他负变化称“减”，正变化称“加”。
- **根据现状整理：**任意形状的外边界使用“左侧边界塑形/右侧边界塑形”等中性名称，不自动称作袖窿。
- **根据现状整理：**显式左右镜像轮廓只用左侧代表段展示规律，并提示右侧镜像编织。
- **根据现状整理：**README 写有“分离区域警告”，状态层也能识别一行多段，但当前页面没有独立警告入口。
- **待确认：**这些几何差值是否足以成为实际可执行编织说明。

## 五、正确结果

**部分确认：**最终结果应明确告诉用户从哪里起针、按哪个方向、在哪些行对哪一侧加减多少针、何时分片或连接，并可用于实际编织。

**待确认：**当前结果没有指定正反面行、加减针技法、平收顺序、同时发生操作的先后、边针和花样保持方式，因此不能认定为完整可执行方案。

## 六、输入与输出

- 用户输入：每对象编织方向；其余输入来自密度、轮廓、取整和离散策略。
- 系统读取：按物理高度排列的各行针段、针段首尾针号、边界段位置和可选镜像约束。
- 系统计算：编织行号、源物理行、该行针数、左右变化、中心变化、分片状态、各肩变化和压缩阶段。
- 系统输出：工具栏摘要、边界段卡片、编号标记和 PNG 中的编织说明。

## 七、数据保存与更新

- 只保存每个对象的编织方向，不保存逐行指令或压缩规则。
- 密度、画布、轮廓、取整、离散策略或方向变化后，指令重新生成。
- 删除或合并对象时清理对应方向；新对象当前默认自下而上。
- 方向切换可撤销、重做并自动保存。
- 卡片手工位置和展开状态不属于编织方案数据，不随方案保存。

## 八、编织与计算规则

### 当前算法行为

- 自下而上按物理行由低到高编号，自上而下反序编号；第一有效行编号为 1。
- 左边变化＝前一行左端针号－当前行左端针号；右边变化＝当前行右端针号－前一行右端针号。
- 规则中的“每几行”＝本次变化行号－上一次同一边界发生变化的行号；外边界从第 0 行算起，领口侧从分片行算起。
- 同间隔、同针数、同操作的相邻阶段合并重复次数。
- 领口中间收针数取两个新针段之间的空缺；连接时中间加起针数取原两个针段间空缺。
- 水平起始边显示起针；末端水平边显示平收或肩部保留和平织说明。

### 产品风险

- “每几行”没有区分正面和反面；现实中很多塑形只在特定面操作。
- 正负针数只能说明数量，不能说明左上二并一、右上二并一、绕加、扭加、套收等具体技法。
- 外侧一次减多针自动称为平收，未验证是否适合所有部位或方向。
- 一行两段被固定解释为左右肩/领口，对其他开口、口袋或两个独立织片可能错误。
- 方向反转可把减针变加针并改变纵向取整固定边，但并不自动改写为符合该工艺的起针和连接方法。
- 标注按“最近服装边界”匹配轮廓段，复杂几何可能归到错误边界。

### 用户确认状态

现有测试证明计算内部一致，不证明实际编织合理；所有具体规则均未取得用户确认。

## 九、与其他功能的关系

- 直接依赖[针格图解生成](./针格图解生成.md)的逐行针段。
- 间接依赖[编织密度与画布尺寸](./编织密度与画布尺寸.md)和[形状绘制与轮廓编辑](./形状绘制与轮廓编辑.md)。

- 方向和上游数据改变后，所有相关卡片、编号和摘要必须同步更新。

## 十、不同设备的操作方式

- 鼠标：在绘版查看全部卡；针格模式点击轮廓段；点击方向按钮；可拖动卡片。
- 触控：卡片按钮和拖动在触控分支前处理，理论上可用；但针格模式的轮廓触控点击当前被忽略，无法按提示选择段。
- Apple Pencil：理论上可点轮廓段和卡片控件，真实设备未验证。
- iPad 横屏：卡片在画布左右自动排列，较矮视口会压缩为一张展开、其余折叠。
- iPad 竖屏：画布更窄，卡片可能遮挡较多空间；可拖动但位置不保存。

## 十一、异常与边界情况

- 没有针格时显示“未落入针格”。
- 开放路径显示“开放路径不形成织片”。
- 三段以上显示不支持归纳；但当前页面缺少总览警告，用户可能只在特定卡中发现。
- 一行没有变化时显示不加不减；直边尝试显示实际平织行数。
- 初始即为两段时显示两片分别起针。
- 中途出现零针空行时可能被判不支持，没有“断纱后重新起针”等正式产品语义。
- 复杂轮廓的多个段可能生成重复说明；页面会按相同过程去重，但去重口径未确认。

## 十二、必须保持不变的行为

- **根据现状整理：**每对象方向独立，切换后行号和规则同步重算。
- **根据现状整理：**左右边界分别计算，阶段顺序不被排序打乱。
- **根据现状整理：**不支持的结构不会伪装成已归纳方案。
- **根据现状整理：**镜像轮廓避免重复两套相同卡片。
- 具体领口、肩部和平收用语尚未确认，不能作为永久不可变业务标准。

## 十三、验收标准

- [ ] 自下而上和自上而下使用正确物理行顺序并更新所有标注。
- [ ] 一段到一段的左右加减针分别计算。
- [ ] 一段到两段、两段到一段、初始两段和三段以上得到不同且明确状态。
- [ ] 压缩规律保持操作顺序，间隔、针数和次数可由逐行结果复核。
- [ ] 领口、肩部、直边、末端和镜像卡片显示与针格位置一致。
- [ ] 上游变化后不保留过期指令或编号。
- [ ] 触控和 Pencil 可选择段、切换方向、展开和拖动卡片。
- [ ] 实际编织专家确认前，界面或文档不把算法结果宣传为已验证针法。

## 十四、待确认问题

1. 产品需要支持平面往返、圈织还是两者？加减针可发生在哪些正反面行？影响“每几行”的实际执行。
2. 每种边界变化应推荐哪些具体加针、减针或平收技法？影响方案是否可直接照做。
3. 同一行左右侧、领口和外侧同时变化时，操作顺序如何表达？影响逐行指令。
4. 一行两段何时代表领口左右肩，何时代表两个独立织片或其他开口？影响结构识别。
5. 多针减少是否都称平收；自上而下时对应操作是否应改为加起或其他技法？影响方向切换。
6. 压缩规则是否必须按正面行节奏、花样重复和成对对称调整？影响可执行性。
7. 三段以上和纵向断开结构应阻止使用、提供手工标注，还是扩展自动规划？影响复杂织片支持。
