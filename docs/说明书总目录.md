> 建档日期：2026-09-02

## 一、推荐阅读顺序

1. 先读[产品总览](./产品总览.md)，理解最终目标、用户流程、核心数据和全局原则。
2. 再按本页功能目录进入本次需求涉及的功能说明。
3. 修改前查看[回归验收清单](./回归验收清单.md)中的对应项目和关联功能。
4. 需要判断某条规则是否经过确认时，查看[产品决策记录](./产品决策记录.md)。
5. 遇到产品意图不明时，先看本页“高优先级待确认问题”，再进入功能文档的“待确认问题”。

## 二、文档状态定义

| 状态 | 含义 |
|---|---|
| 已确认 | 用户已经明确确认该产品行为，并能找到可靠依据 |
| 部分确认 | 目标或部分规则已经确认，仍有会影响结果的待确认内容 |
| 根据现状整理 | 只能从当前代码、页面、测试或既有说明观察得出 |
| 待确认 | 无法确定产品意图，不应自行决定 |
| 待整理 | 尚未完成分析 |

状态描述的是产品规则的确认程度，不代表功能是否已经写完，也不代表当前实现正确。

## 四、功能之间的主要关联

1. 用户输入的小样和画布尺寸先形成编织密度与画布针格规模。
2. 用户绘制或导入的轮廓以厘米保存；轮廓尺寸结合密度生成针数、行数候选。
3. 非整数尺寸需要选择取整方向；选择会改变用于针格化的织片整体宽高。
4. 轮廓、密度、取整选择、离散策略和编织方向共同决定针格与逐行加减针说明。
5. 画布显示、编织标注和图片导出读取上述计算结果。
6. 方案库保存源数据和部分界面状态；重新打开后再计算针格和指令。

详细的数据关系只在[产品总览](./产品总览.md#七核心数据及其关系)维护。

## 五、高风险影响关系

| 上游变化 | 需要同步重算或复核 | 主要风险 |
|---|---|---|
| 小样针数、行数或小样厘米尺寸 | 画布针格、所有尺寸换算、所有针格、所有加减针说明 | 一个输入会改变全方案；实际小样测量口径尚未确认 |
| 画布尺寸 | 网格范围、裁剪、适应视图、导出布局 | 图形可能被裁剪；画布自身采用四舍五入，与织片取整流程不同 |
| 轮廓节点、控制柄、位置或整体尺寸 | 分段尺寸、针格、起针数、总行数、领口/分片识别、加减针 | 几何微调可能跨过针格边界并改变多行结果 |
| 横向或纵向取整选择 | 织片整体实际宽高、固定边、针格、编织说明 | 当前一次选择应用于同一织片整个轴向，是否符合各部位需求待确认 |
| 离散策略 | 各行针段和所有加减针 | 三种策略的实际编织用途与默认选择尚未确认 |
| 编织方向 | 取整后的纵向固定边、行号顺序、加减针方向和标注 | 不只是文字反转，会改变实际针格位置 |
| 多个闭合图形重叠或分离 | 总画布针格并集、每对象独立计划 | “多个对象是多个织片还是一个组合织片”尚未确认 |

## 六、已发现的现状矛盾

- README 和底层测试说明开放路径会生成一针格宽轨迹，但编辑器合并显示针格时排除了开放路径；页面又明确标注“开放路径不形成织片”。正确用途待确认，详见[针格图解生成](./功能说明/针格图解生成.md#十四待确认问题)。
- README 声称存在“分离区域警告”，状态层也会识别分离区域，但当前页面没有展示该警告。详见[编织方向与加减针方案](./功能说明/编织方向与加减针方案.md#十一异常与边界情况)。
- 项目规则要求触控完成核心流程；当前画布把单指触控固定解释为平移，并忽略触控点击，无法仅靠触控完成绘制、选择和节点编辑。详见[形状绘制与轮廓编辑](./功能说明/形状绘制与轮廓编辑.md#十不同设备的操作方式)。
- 状态层和测试支持矩形、三角形、圆形、椭圆和多边形，但当前工具栏只提供路径的新建入口；这些图形仍可能从旧存档或导入文件出现。详见[形状绘制与轮廓编辑](./功能说明/形状绘制与轮廓编辑.md#四当前可观察行为)。

## 七、高优先级待确认问题

完整问题保留在各功能文档的“待确认问题”章节。建议优先确认：

1. 实际成衣轮廓代表净尺寸、成衣尺寸还是包含松量和缝份的织片尺寸？影响密度、尺寸换算、针格和全部加减针。
2. 针数和行数的取整应依据什么编织规则，是否要满足花样倍数、罗纹倍数、左右对称和缝份？影响尺寸取整、针格和加减针可执行性。
3. “每几行加/减几针”的规则是否必须限定在正面行、使用何种加减针或平收方式，以及同一行多侧操作顺序？影响加减针方案能否实际执行。
4. 多个闭合图形应视为独立织片、一个织片的组合区域，还是允许两者由用户指定？影响针格合并、分离区域和方案说明。
5. 开放路径究竟是辅助线、实际一针格宽结构，还是尚未完成的轮廓片段？影响显示、保存、取整和图解输出。
6. 三种离散策略分别适用于什么编织场景，默认值是否应固定为“针格中心”？影响边界尺寸和加减针规律。
7. iPad 触控是否必须与 Apple Pencil 一样支持绘制和节点编辑，还是触控只负责导航、Apple Pencil 负责绘制？当前项目规则要求完整等价路径，若要例外必须明确确认。
